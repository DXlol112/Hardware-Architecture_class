# Рабочий цикл процессора

Конспект по презентации «проц».

## Программа, данные и команды

**Программа** — последовательность команд, которая преобразует входные данные в результат. Команды выполняет процессор. В рассматриваемой схеме команды и данные программы хранятся в **оперативной памяти (ОП)**.

Процессор и память соединяются системной шиной. Она включает линии данных, адреса и управления.

![Связь процессора и оперативной памяти через системную шину](../../.github/assets/lesson_04/Системная_шина_процессора_и_памяти.png)

### Представление данных

- Числа хранятся в двоичной системе счисления, в форматах с фиксированной или плавающей точкой.
- Символы представляются двоичными кодами.
- Двоичные векторы представляют собой последовательности битов. Над ними выполняются поразрядные логические операции.

В приведённом примере отдельный бит обозначает знак: `0` — положительное число, `1` — отрицательное.

![Двоичное представление числа со знаком](../../.github/assets/lesson_04/Представление_двоичного_числа.png)

Пример на слайде:

    1101101₂ = 1 + 4 + 8 + 32 + 64 = 109₁₀

### Представление команд

**Команда** задаёт операцию, которую должен выполнить процессор.

В рассматриваемой двухадресной команде три поля:

1. **КОП** — код операции.
2. **A₁** — адрес первого операнда.
3. **A₂** — адрес второго операнда.

Результат в этом примере записывается на место первого операнда.

![Формат двухадресной команды](../../.github/assets/lesson_04/Двухадресный_формат_команды.png)

**Система команд процессора** — набор команд, которые он может выполнять. В него входят арифметические и логические команды, пересылки, переходы и команды ввода-вывода.

В презентации приведён фрагмент системы команд микроконтроллера КМ1816ВЕ51.

![Фрагмент арифметических команд КМ1816ВЕ51](../../.github/assets/lesson_04/Арифметические_команды_КМ1816ВЕ51.png)

## Устройства и регистры

![Упрощённая структурная схема процессора и оперативной памяти](../../.github/assets/lesson_04/Упрощенная_схема_процессора_и_ОП.png)

Обозначения на схемах:

| Обозначение | Назначение |
| --- | --- |
| **УУиС** | Устройство управления и синхронизации, управляет работой остальных устройств |
| **СчАК**, **СК**, **PC** | Счётчик адреса команды, хранит адрес очередной команды |
| **РК** | Регистр команд, хранит выбранную команду во время её выполнения |
| **ПортА** | Порт адреса, подключён к шине адреса |
| **ПортД** | Порт данных, подключён к шине данных |
| **Р1** | Аккумулятор АЛУ, хранит первый операнд, а затем результат |
| **Р2** | Второй регистр операндов АЛУ |
| **РАОП** | Регистр адреса оперативной памяти |
| **РСОП** | Регистр слова оперативной памяти |
| **DC** | Дешифратор кода операции |
| **C** | Генератор синхросигналов |

Длина СчАК зависит от разрядности адреса. Длина РК определяется максимальной длиной команды. Разрядность регистров АЛУ зависит от длины операндов. Разрядность портов соответствует ширине подключённых шин.

### Чтение из ОП

Чтобы прочитать данные:

1. Процессор выставляет адрес нужного слова на шину адреса, в РАОП.
2. Формирует сигнал **ЧтОП**.
3. Считанное слово появляется в РСОП и по шине данных поступает в ПортД.

### Запись в ОП

Чтобы записать данные:

1. Процессор выставляет адрес на шину адреса, в РАОП.
2. Передаёт данные на шину данных, в РСОП.
3. Формирует сигнал **ЗпОП**.

![Регистры и сигналы чтения и записи оперативной памяти](../../.github/assets/lesson_04/Чтение_и_запись_оперативной_памяти.png)

## Пять этапов рабочего цикла

В презентации разобрана двухадресная арифметическая или логическая команда.

Её выполнение проходит через пять этапов:

1. Выборка команды из ОП.
2. Выборка операндов из ОП.
3. Выполнение операции в АЛУ.
4. Запись результата в ОП.
5. Продвижение счётчика команд.

На схемах `y₁, y₂, …` — управляющие сигналы, а `x₁, x₂, …` — осведомительные сигналы. Запись `РК := ПортД` означает копирование содержимого ПортД в РК.

### 1. Выборка команды

| Шаг | Сигнал | Действие |
| --- | --- | --- |
| 1 | `y₁` | `ПортА := СчАК` |
| 2 | `y₂` | `ЧтОП` |
| 3 | `y₃` | `РК := ПортД` |

Сначала на шину адреса поступает адрес команды. Затем память выдаёт команду по шине данных, и процессор сохраняет её в РК.

![Выборка команды и её загрузка в РК](../../.github/assets/lesson_04/Выборка_команды.png)

### 2. Выборка операндов

Первый операнд:

| Шаг | Сигнал | Действие |
| --- | --- | --- |
| 4 | `y₄` | `ПортА := A₁` |
| 5 | `y₂` | `ЧтОП` |
| 6 | `y₅` | `Р1 := ПортД` |

Адрес первого операнда берётся из РК. После чтения из ОП операнд помещается в аккумулятор Р1.

![Чтение первого операнда в аккумулятор](../../.github/assets/lesson_04/Выборка_первого_операнда.png)

Второй операнд:

| Шаг | Сигнал | Действие |
| --- | --- | --- |
| 7 | `y₆` | `ПортА := A₂` |
| 8 | `y₂` | `ЧтОП` |
| 9 | `y₇` | `Р2 := ПортД` |

![Чтение второго операнда в Р2](../../.github/assets/lesson_04/Выборка_второго_операнда.png)

### 3. Выполнение операции в АЛУ

На десятом шаге код операции из РК поступает на дешифратор DC.

На выходе дешифратора формируется осведомительный сигнал `xᵢ = 1`. УУиС выдаёт соответствующий управляющий сигнал `yᵢАЛУ`, который запускает нужную микропрограмму АЛУ.

После операции результат находится в Р1.

![Запуск операции в АЛУ по коду команды](../../.github/assets/lesson_04/Выполнение_операции_в_АЛУ.png)

### 4. Запись результата

| Шаг | Сигнал | Действие |
| --- | --- | --- |
| 11 | `y₈` | `ПортД := Р1` |
| 12 | `y₄` | `ПортА := A₁` |
| 13 | `y₉` | `ЗпОП` |

Результат передаётся на шину данных. На шине адреса выставляется A₁, после чего результат записывается на место первого операнда.

![Запись результата из аккумулятора в оперативную память](../../.github/assets/lesson_04/Запись_результата_в_ОП.png)

### 5. Продвижение счётчика команд

На четырнадцатом шаге:

    y₁₀: СчАК := СчАК + L

**L** — длина выполненной команды в байтах. После увеличения СчАК указывает на следующую команду.

Этот этап можно выполнить сразу после выборки команды.

![Увеличение счётчика на длину команды](../../.github/assets/lesson_04/Продвижение_счетчика_команд.png)

## Начало работы процессора

В упрощённой схеме предусмотрены внешние сигналы **Set** и **Reset** для включения и выключения УУиС.

После включения УУиС формирует сигнал `y₀`, который устанавливает в СчАК начальный адрес программы.

![Сигналы Set, Reset и установка начального адреса](../../.github/assets/lesson_04/Set_и_Reset_процессора.png)

На условном обозначении процессора показаны:

- выводы адреса `A` и данных `D`;
- питание и общий провод;
- тактовый вход;
- `RD, WR` для чтения и записи ОП;
- `IN, OUT` для обмена с периферийными устройствами.

![Обобщённое обозначение процессора и его выводы](../../.github/assets/lesson_04/Внешние_выводы_процессора.png)

УУиС повторяет последовательность управляющих сигналов рабочего цикла. Если возникло прерывание, между выполнениями команд включается микропрограмма его обработки.

![Последовательность управляющих сигналов рабочего цикла](../../.github/assets/lesson_04/Последовательность_управляющих_сигналов.png)

## Пошаговый пример сложения

Условия примера:

- В системе команд 256 команд, поэтому КОП занимает 8 бит.
- Команда содержит адреса двух операндов.
- ОП состоит из байтов, у каждого байта есть свой адрес.
- Шина данных имеет ширину 32 бита: за одно обращение можно передать от 1 до 4 байтов.
- Шина адреса имеет ширину 8 бит: адресуется до `2⁸ = 256` байтов ОП.
- Команды и данные находятся в общей памяти. Это принстонская архитектура.
- Операнды занимают по 2 байта. Адресом операнда считается адрес его первого байта.

### Выборка команды

В СК находится `00110110₂ = 54₁₀`.

Команда занимает три байта, начиная с адреса 54:

| Поле | Двоичное значение | Значение |
| --- | --- | --- |
| КОП | `11011101` | Код операции сложения в примере |
| A₁ | `01110110` | Адрес первого операнда: 118 |
| A₂ | `01111000` | Адрес второго операнда: 120 |

Процессор выставляет адрес 54, считывает команду и сохраняет её в РК.

![Выборка трёхбайтовой команды из памяти](../../.github/assets/lesson_04/Загрузка_трехбайтовой_команды.png)

### Выборка данных и сложение

Первый операнд загружается из байтов по адресам 118–119 в Р1. Второй — из байтов по адресам 120–121 в Р2.

Значения в регистрах на схеме:

    Р1 = 0001001011010001₂
    Р2 = 0011011111101110₂

![Оба операнда загружены в регистры АЛУ](../../.github/assets/lesson_04/Операнды_в_регистрах_АЛУ.png)

АЛУ выполняет сложение:

    0001001011010001
    0011011111101110
    ----------------
    0100101010111111

Результат появляется в аккумуляторе Р1.

![Результат сложения в аккумуляторе](../../.github/assets/lesson_04/Результат_сложения_в_аккумуляторе.png)

### Запись и следующая команда

Результат записывается в байты ОП по адресам 118–119, на место первого операнда.

СК увеличивается на длину команды:

    СК := 54 + 3 = 57
    СК = 00111001₂

После этого цикл начинается заново для команды по адресу 57.

![Запись суммы в память и продвижение СК к адресу 57](../../.github/assets/lesson_04/Запись_суммы_и_следующая_команда.png)

## Завершение операции и признаки результата

Более подробная схема АЛУ содержит выходы результата, признаков, исключительных ситуаций и сигнала «занято/свободно».

В структуру процессора добавляются:

- **РПР** — двухразрядный регистр признака результата;
- **РФ** — регистр флагов прерываний.

![АЛУ с шиной признаков, шифратором, РПР и РФ](../../.github/assets/lesson_04/АЛУ_признаки_и_флаги_прерываний.png)

### Сигнал «занято/свободно»

После запуска операции АЛУ устанавливает `ZАЛУ = 1`: оно занято.

Процессор ожидает, пока АЛУ установит `ZАЛУ = 0`. Это означает, что операция закончена, результат находится в Р1 и можно переходить к записи результата.

На схеме этот сигнал соответствует линии **ШАЛУ(8)**.

![Передача осведомительного сигнала ZАЛУ устройству управления](../../.github/assets/lesson_04/Управляющие_сигналы_УУиС.png)

### Код признака результата

Для `add, sub, inc, dec, and, or, xor` АЛУ формирует четырёхразрядный унитарный код. Шифратор **Coder** преобразует его в двухразрядный код для РПР.

| Линия ШАЛУ | Признак | Код в РПР |
| --- | --- | --- |
| `ШАЛУ(0)` | Результат равен нулю | `00` |
| `ШАЛУ(1)` | Результат меньше нуля | `01` |
| `ШАЛУ(2)` | Результат больше нуля | `10` |
| `ШАЛУ(3)` | Переполнение с фиксированной точкой | `11` |

### Флаги исключительных ситуаций

Кроме признака результата, АЛУ формирует флаги:

- переполнения с фиксированной точкой;
- переполнения порядка;
- исчезновения порядка;
- потери значимости;
- деления на ноль.

Эти флаги сохраняются в РФ для последующей обработки прерывания.

На схеме делению на ноль соответствует **ШАЛУ(7)**, а занятости — **ШАЛУ(8)**. В текстовом перечне одного слайда деление на ноль также подписано номером 8; здесь использованы обозначения структурной схемы.

### Уточнение этапа записи результата

Кроме передачи результата в память выполняются:

    y₈:  ПортД := Р1
    y₁₁: РПР(0:1) := Coder(ШАЛУ(0:3))
    y₁₂: РФ(0:4) := ШАЛУ(3:7)
    y₄:  ПортА := A₁
    y₉:  ЗпОП

РПР изменяется только для указанных арифметических и логических команд. Другие команды должны сохранять его содержимое.

Если `ШАЛУ(3:7) = 00000`, исключительная ситуация при операции не возникла.

Разрядность РФ больше числа флагов АЛУ: запросы прерываний могут поступать также от таймеров и внешних устройств.

![Сигналы сохранения признака результата и флагов](../../.github/assets/lesson_04/Сохранение_признака_результата_и_флагов.png)

## Команды перехода

После обычной арифметической или логической команды СК продвигается к следующей команде.

Чтобы перейти к произвольной команде, организовать ветвление или цикл, используются **команды передачи управления**.

### Условный переход по маске

Формат команды в рассматриваемом примере:

| Поле | Разряды РК | Назначение |
| --- | --- | --- |
| КОП | `0:7` | Код операции |
| M | `8:11` | Маска перехода |
| A | `12:n` | Адрес перехода |

Маска определяет, какие признаки результата разрешают переход.

| Код РПР | Бит маски | Условие |
| --- | --- | --- |
| `00` | `РК(8)` | Результат равен нулю |
| `01` | `РК(9)` | Результат меньше нуля |
| `10` | `РК(10)` | Результат больше нуля |
| `11` | `РК(11)` | Переполнение с фиксированной точкой |

![Соответствие признака результата разряду маски](../../.github/assets/lesson_04/Маска_перехода_и_признак_результата.png)

Порядок проверки:

1. Если `M = 0000`, переход не выполняется.
2. Если адрес `A = 0`, переход также не выполняется.
3. Если `M = 1111` и адрес ненулевой, переход выполняется безусловно.
4. В остальных случаях проверяется бит маски, соответствующий текущему РПР.
5. Если этот бит равен 1, адрес A загружается в СчАК. Иначе выполнение продолжается со следующей команды.

СчАК заранее продвинут после выборки команды перехода. Переход заменяет это значение адресом A. Содержимое РПР при этом не изменяется.

![Алгоритм условного перехода по маске](../../.github/assets/lesson_04/Алгоритм_условного_перехода_по_маске.png)

### Схема проверки условия

В структурной схеме осведомительные сигналы обозначают:

- `x₁` — маска нулевая;
- `x₂` — адрес нулевой;
- `x₃` — все биты маски равны 1;
- `x₄` — текущий признак результата разрешён маской.

При выполнении условия управляющий сигнал `y₁` загружает адрес из РК в СчАК. Нумерация сигналов в этой схеме своя.

![Устройства для выполнения перехода по маске](../../.github/assets/lesson_04/Схема_выполнения_условного_перехода.png)

Для вычисления `x₄` дешифратор РПР выбирает один из четырёх признаков. Элементы И соединяют его с соответствующим битом маски, а элемент ИЛИ объединяет результаты.

![Логическая схема проверки маски перехода](../../.github/assets/lesson_04/Проверка_маски_перехода.png)

Для объёма памяти `EОП = 2ᴺ` байтов разрядность адреса равна:

    N_A = log₂(EОП)

Такую разрядность имеют СчАК и поле адреса A. Например, для 256 байтов нужны 8 адресных битов.

## Прерывания и переключение программ

**Прерывание** временно переводит процессор от текущей программы к программе обработки события. После обработки процессор возвращается к прерванной программе.

### Источники прерываний

1. **Исключительные ситуации при выполнении команды**: деление на ноль, переполнение, исчезновение порядка, потеря значимости.
2. **Внешние устройства**: запросы ввода-вывода, события клавиатуры.
3. **Таймер**: сигнал для переключения между программами.

В презентации примером внешнего события служит нажатие `Num Lock`: обработчик меняет состояние индикатора, после чего продолжается текущая программа.

**Маскирование** отменяет обработку выбранного прерывания. Не все прерывания можно маскировать.

### Мультипрограммный режим

Каждой программе выделяется небольшой **квант времени**. В презентации приведён пример `τ = 1/30 с`.

Когда квант заканчивается, возникает прерывание таймера, и процессор переключается на другую программу. При возврате выполнение продолжается с сохранённого места.

### Регистры флагов и масок

- **РФ** хранит флаги возникших прерываний.
- **РМ** хранит маски прерываний.

Каждому источнику соответствует свой бит. В рассматриваемой схеме установка бита РМ в 1 запрещает обработку соответствующего маскируемого прерывания.

## Таблица векторов прерываний и стек

В рассматриваемой организации памяти первые `n` слов выделены под **таблицу векторов прерываний (ТВП)**.

Каждой причине прерывания соответствует слово таблицы. В нём находится команда безусловного перехода на адрес Aᵢ программы обработки этого прерывания.

Для сохранения адреса возврата используется **стек** и **указатель стека (УС)**.

![Таблица векторов, стек и программа обработки прерывания](../../.github/assets/lesson_04/Стек_и_таблица_векторов_прерываний.png)

Стек работает по принципу **LIFO**: последний записанный элемент извлекается первым.

В этой учебной схеме УС указывает на верхнее свободное слово:

- при записи значение помещается в `ОП[УС]`, затем УС увеличивается;
- при извлечении УС сначала уменьшается, затем читается `ОП[УС]`.

### Порядок обработки прерывания

После очередной команды процессор проверяет РФ. Если обнаружен флаг `Fᵢ = 1` незамаскированного прерывания:

1. Сохраняется СК, который уже указывает на следующую команду:

        ОП[УС] := СК
        УС := УС + 1

2. В СК загружается адрес соответствующего слова ТВП:

        СК := i

3. Выполняется находящаяся там команда перехода:

        JMP Aᵢ
        СК := Aᵢ

4. Выполняется программа обработки прерывания.
5. Последняя команда обработчика, `RETI`, извлекает адрес возврата:

        УС := УС - 1
        СК := ОП[УС]

После этого продолжается прерванная программа.

Если установлено несколько флагов, запросы опрашиваются с учётом принятого порядка или приоритетов. Возникшие незамаскированные прерывания обрабатываются.

### Сохранение состояния программы

В разобранном варианте автоматически сохраняется только адрес возврата.

Если обработчик изменяет регистры, необходимые прерванной программе, программист должен сохранить их при входе в обработчик и восстановить перед `RETI`. Это относится, например, к РПР, другим специальным регистрам и РОН.

В других системах вместе с адресом возврата автоматически сохраняются и восстанавливаются дополнительные регистры. Их состояние объединяется понятием **«слово состояния программы» — ССП, или PSW**.
